# T1 — Rebuild menus by observing RecentFiles

## What to do

1. Remove `crate::canvas::actions::set_menus(cx)` from `src/settings/recent.rs:100`.
2. Register one `cx.observe_global::<RecentFiles>(|cx| set_menus(cx))` where actions are installed (`canvas/actions.rs`, next to the initial `set_menus` call at line 110), detached for the app lifetime.
3. Keep the initial `set_menus` call so the menu exists before any change.

## Context

Call sites that mutate the list: `main.rs:84`, `canvas/view.rs:1498,1505,1512,1564,1621`, `canvas/actions.rs:108`. `RecentFiles` must be public enough for the observer (`settings::recent`).

The GPUI test platform stores installed menus (`TestPlatform::set_menus` / `get_menus`, gpui-pre 0.3.9 `platform/test/platform.rs:700-706`) and `App::get_menus` is public, so the test can read the real menu bar.

Asserting the `RecentFiles` global is NOT sufficient: `recent::update` sets it regardless of the menu rebuild (false positive).
- Verify red: with the `set_menus` call removed and no observer, the test MUST fail; then add the observer and see it pass.
